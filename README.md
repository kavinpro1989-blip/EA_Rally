# EA Rally – physics engine & mechanical tuning backend

Deterministic, SI-unit, zero-dependency rally vehicle simulation in ES-module JavaScript (runs in Node ≥ 20 and in the
browser, Three.js compatible). It reads `/config/*.json`, exposes fixed-step simulation ticks and a JSON telemetry
stream, and ships an adapter that plugs it into the existing UI (`/ui_and_integration`) without editing UI files.

```
core_physics/
  math/         vectors, quaternions, lookup tables (PCHIP / bilinear), seeded RNG, constants
  drivetrain/   engine, turbo, ECU, clutch, gearbox, differentials, full powertrain
  chassis/      6-DOF body + 4 hubs, tyre (Pacejka/Brush), suspension, aero, surfaces, terrain interface
systems/
  stage/              GPS parser, geodesy, 3D spline, banking/crown, pacenotes, progress tracking
  damage/             cooling & radiator punctures, intercooler fouling, tie-rods, tyres, turbo, brakes (fade)
  surface_evolution/  gravel sweeping, rutting, compaction, repose relaxation, racing-line ageing
sim/            Simulation facade, telemetry, config loading/validation, autopilot, UI integration
config/         engine, drivetrain, chassis, tires, surfaces, damage, simulation, gps_stage_schema (.json)
stages/         demo_stage.json (synthetic, generated by tools/generate_demo_stage.js)
test/           170 tests (node:test)      tools/  stage generator, benchmark, browser smoke test
```

## Quick start

```bash
npm test                    # 170 tests, ~20 s
node tools/bench.js         # throughput (≈13–16× real time on the demo stage, 2 ms step)
npm run demo-stage          # regenerate stages/demo_stage.json
```

```js
import { Simulation, Autopilot } from './sim/index.js';
import { loadConfigDir, loadStageFile } from './sim/config_node.js';       // browser: loadConfigUrl from ./sim/config_web.js

const sim = new Simulation(loadConfigDir('./config'), { stageJson: loadStageFile('./stages/demo_stage.json') });
sim.setInputs({ throttle: 1, gear: 1, alsSwitch: true });                  // inputs latch at each tick
sim.update(1 / 60);                                                        // fixed-step accumulator; returns ticks run
const t = sim.getTelemetry();                                              // plain JSON snapshot (see sim/telemetry.js)
const r = sim.getRenderState();                                            // interpolated body/wheel transforms
sim.subscribe((snap) => hud.render(snap), { hz: 30 });                    // {seq, tick, hash, telemetry, render}
```

Inputs: `throttle brake clutch(null = auto) steer(+right) handbrake shiftUp shiftDown gear ignition starter alsSwitch
launchSwitch centerDiffLock brakeBias`. Events (`sim.drainEvents()`): shifts, stalls, pacenote calls, stage start/split/finish,
off-course, radiator punctures, bent tie-rods, gear grind/pop-out, body impacts, engine seizure.

## Conventions

* **Units**: SI everywhere in code (m, kg, s, N, Pa, K, rad). Config keys say when they are rpm / kPa / deg.
* **Engine world frame** (right-handed, Y up, Three.js compatible): `+X East, +Y Up, +Z South`. Car body frame:
  `+X forward, +Y up, +Z right`. Heading is a compass bearing (0 = north, clockwise). Curvature `+` = left; bank `+` = right side down.
* **UI world frame** (the stage compiler maps latitude to +Z): `+Z = North`, i.e. mirrored in Z. The integration layer converts
  positions `z → -z`, quaternions `(x,y,z,w) → (-x,-y,z,w)`, and hands the viewport the compass bearing as `rotation.yaw`.
* Wheel order everywhere: FL, FR, RL, RR.

## What is modelled

**Drivetrain** – Torque is referenced to the measured WOT dyno curve and scaled by actual charge density (throttle × plenum
pressure × intercooled temperature) and ignition efficiency, so the table is reproduced exactly at dyno boost and lag, heat-soak,
altitude, retard and boost leaks act through physics. Mean-value turbo (shaft inertia, turbine from an orifice-flow expansion
ratio, compressor head/flow map with surge back-flow, plenum dynamics, pneumatic wastegate with ECU duty, blow-off valve,
intercooler with blockage). ECU: throttle/boost maps, PI idle and boost control, rev limiter, launch control, thermal derate and
**anti-lag** (cracked throttle + heavy retard + enrichment; boost is retained because the hot exhaust keeps the turbine driving the
shaft). Dry clutch with impulse-based stick/slip (unconditionally stable), thermal fade and wear. Sequential or H-pattern gearbox
(grind, synchro/dog wear, pop-out, flat-shift cut, auto-blip). AWD/RWD/FWD with centre, front and rear friction-pack LSDs
(preload, power/coast ramp angles, controllable lock), locked, open and viscous types; also solved with the deadbeat stick torque.

**Tyres & surfaces** – Transient carcass slip (relaxation length; no singularity at standstill) feeding either an anisotropic
**Brush** model or **Pacejka** magic-formula curves combined through the normalised slip vector (friction ellipse). Grip depends on
load, rubber temperature, hot gas-law pressure, wear and the surface; surfaces are **multi-layer stacks** (e.g. 4 cm gravel over
packed dirt) blended by penetration depth. Two-node thermal model, wear, punctures. Compounds: tarmac, gravel, studded snow.

**Chassis** – Sprung 6-DOF rigid body plus four hubs with vertical travel and unsprung mass. Per corner: spring with preload,
series helper/tender spring, 4-regime damper (slow/fast × bump/rebound with knee velocities), progressive damped bump stop, droop
strap, anti-roll bars (torque transfer), camber/toe gain. Tyre envelope sampling over three points of the wheel circumference,
aero (drag, downforce, side force, wind), skid-plate and body-hull (bumper/roof) ground contact so rolled cars stay on the ground.

**Stage** – `config/gps_stage_schema.json` is the single source of truth: the parser validates stage files against it with a small
built-in JSON-Schema engine, converts WGS84 lat/lng/elevation arrays to the local frame (exact ECEF → ENU), fits a centripetal
Catmull-Rom spline, resamples by arc length, smooths GPS noise, derives heading/curvature/grade/vertical curvature, banking
(measured or procedural superelevation + seeded noise) and a crowned cross-section with shoulders and verge. **Pacenotes** are
generated (direction, severity 1–6 or reversed, hairpin/square, long/tightens/opens/off-camber/into, crests, jumps, dips) or
authored/merged, and `PacenotePlayer` calls them speed-dependently without overlap.

**Damage & evolution** – Radiator punctures → coolant loss → air-lock → overheating → ECU derate → seizure; intercooler fouling
(mud/snow/dust) → charge temperature and power loss; bent tie-rods from whole-episode impact energy (toe error → scrub); tyre
leaks; turbo overspeed/over-temperature → boost leak; brake disc/fluid/pad thermal fade and wear; clutch and gearbox wear;
seeded stone strikes. `SurfaceEvolution` keeps a lateral grid per metre of stage: loose layers are swept sideways into berms
(volume conserved, biased by slide direction, scaled by load/slip), ruts form toward bearing-capacity depth, snow compacts into
packed snow, berms relax to the angle of repose; ruts feed back into terrain height/normal and rolling resistance.

## Determinism and UI synchronisation

* State after N ticks is a pure function of (config, stage, seed, inputs latched per tick). All randomness is a seeded PRNG that is
  part of the state. Verified by tests: identical runs are bit-identical, chunking of `update(dt)` does not matter, and
  `serialize()` → `restore()` resumes exactly (including damage, stage progress and the evolved surface).
* `sim.getSnapshot()` / `subscribe()` deliver `{seq, tick, time, hash, telemetry, render}`; `hash` lets a UI replica detect divergence.
* Non-finite state throws `PhysicsStateError` immediately; body rates and speeds are limited as a last-resort safety net.

## UI integration (`/ui_and_integration`, `main.js`)

`sim/ui_integration.js` adapts the engine to the UI's existing contracts **without modifying UI files**. Adding one call to
`main.js` after `stateStore.physicsBridge = physicsBridge` switches the singleton from its placeholder maths to the engine:

```js
import { installRallyEngine } from './sim/ui_integration.js';
import { loadConfigUrl } from './sim/config_web.js';
installRallyEngine(physicsBridge, { eventBus, RALLY_EVENTS, stateStore, config: await loadConfigUrl('/config') });
```

It replaces `_stepPhysics`, `_broadcastTelemetry`, `resetVehicle`, `shiftGear` on the bridge; the UI's loop, input smoothing, hotkeys
and listeners keep working. What it does:

| UI contract | Mapping |
|---|---|
| `TELEMETRY_UPDATE` payload (`config/telemetry_schema.json`) | built from the engine; validated against that schema in tests and in the browser. `activePacenote` is omitted (not `null`) when idle. Extras: `position`, `rotation`, `quaternion`, `wheelTransforms`, `damage`, `stateHash` (UI coordinates). |
| Suspension `travelMm` | anchored so static ride reads 140 of 280 mm (the viewport offsets wheels by `travelMm − 140`); `compressionPct` is the true fraction of physical travel; exact values under `physical`. |
| `currentTuning` | springs N/mm (wheel rate = rate × MR²), damping N·s/m at the damper, anti-roll N/mm at the wheel, ride height mm → spring preload (baseline 140/150), diff locks % → clutch-pack ramp gain (100 % = can hand over all input torque), `peakBoostBar` absolute, peak torque and `maxRpm` rescale the curve/limiter, psi → kPa, compound name → engine compound, brake bias/torque/handbrake. Out-of-range values are clamped; `link.report` lists applied/ignored/warnings/info. |
| Stage (`rally_stage_schema.json`) | `waypoints[].lat/lon/elevation/width` → GPS stage (UI `x/y/z`, `camber`, `distance` are derived and not trusted). Surfaces `tarmac/gravel/rocky/snow` → layer stacks. Authored UI pacenotes are used (distances rescaled to the engine path) unless `options.pacenoteSource: 'engine'`. |
| Events | `GEAR_SHIFT`, `PACENOTE_TRIGGER` (UI shape), `BOTTOM_OUT`, `TURBO_BLOWOFF`, `BACKFIRE_POP` (anti-lag/limiter/shift, seeded, audio-only), `VEHICLE_COLLISION`, `NOTIFICATION` (damage, splits, finish). |
| Tuning edits | coalesced into one rebuild per frame; the car keeps its distance, lateral offset, speed and gear. `visual_parts` changes never touch physics. |

Browser verification of the real UI: run `npm run dev` and open `/tools/ui_smoke.html` (boots the unmodified `main.js`, installs
the engine, records `window.__smoke`). Not mapped (UI-only): `visual_parts`, `displacementLiters/cylinders/aspiration`; the UI's
`peakPowerBhp` is cross-checked and reported as info only.

## Known simplifications (be aware before tuning against real data)

* Suspension is a wheel-rate model: no link kinematics (roll centre at ground level, no anti-dive/squat), hubs move only vertically.
* Unsprung masses have no lateral/longitudinal inertia; engine/driveline reaction torque on the body is not modelled separately.
* The only obstacle contact is terrain (tyre envelope, skid plate, bumper/roof points); there is no car-to-car or prop collision.
  `Chassis.applyImpulse()` + `DamageSystem.applyImpact()` are the hooks for one.
* Tyre, thermal, turbo, cooling and surface parameters are plausible rally-class values tuned against behavioural targets (see
  the tests), not measurements of a specific car. Replace them in `/config` with measured data.
* Geometry-derived pacenote radii are accurate to roughly ±30 % on noisy GPS; use `processing.*Smoothing` in the stage file.
* Only JavaScript is provided. No .NET SDK was available to compile or test a C# port, so none is shipped; the math/state code has
  no global state or platform dependencies and maps 1:1 to C# classes.
